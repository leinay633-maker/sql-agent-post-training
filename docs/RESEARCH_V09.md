# v0.9 预注册：从 PTR 出发的在线 RL（执行结果作奖励），对照在线拒绝采样微调

写于 2026-10-13（北京时间），在任何 v0.9 运行之前。协议 `efa-v9-online-rl-v1`。

## 为什么有 v0.9

v0.5–v0.8 都是离线的：先采样、选出执行验证正确的轨迹，再做 SFT 或 DPO。v0.8 的最终家族 PTR（R + 门槛老师补全 + DPO）在 test 上官方 EX 54.9–56.2%，dev 与 validation 已和 235B 老师持平。v0.4 写过在线 RLOO，但没有上过卡，当时用 HF 逐条生成，两轮、384 token，按估算一晚跑不出有意义的步数。

v0.8 的错误分析（`python -m exec_feedback.v9.errors`，test 1501 题）显示，PTR 的错误里，最多的是行列数都对但值不对（约 320 题），其次是行数不对（160）、返回空结果（101）、列数不对（99）。模型几乎每题先查一次数据再提交，平均 2.3 轮，“首次提交后复核”的机制从未触发。这些错误只有在线采样、按执行结果奖惩才能直接针对：模型自己生成的错误轨迹带负信号，对的轨迹带正信号。离线 SFT 只学对的轨迹，DPO 只用 v0.5 那 547 对。

问题：

1. **主问题**：从 PTR 出发，用执行结果作终局奖励做在线 RL（RLOO），能否在 v0.8 的同一协议下继续提升（RL vs PTR）。
2. **机制对照**：同样在线采样、同样步数，只学做对的轨迹（在线拒绝采样微调 RAFT，等价于不减基线的 REINFORCE），和 RL 比。它回答“提升来自负样本和基线，还是只来自更多在线的正确轨迹”（RL vs RAFT）。

## 固定内容

- 题目、Agent 协议、判分：与 v0.8 完全相同（v0.5 注册：pool 6682 / dev 615 / validation 1612 / test 1501；最多 4 步含一次结果复核；上下文 8192，单步 512 token；接受裸 JSON 或恰好一个 ```json 代码块；SQL 限制 10 亿 VM 步、墙钟 30 秒、1 万行、8 MB）。不放宽上下文：v0.8 评测里上下文拒绝几乎为零（test 每个条件 0–1 次），只在采样难题时出现，放宽会让 v0.9 和 v0.8 不可比。
- 学生：`Qwen/Qwen3-4B-Instruct-2507` @ `cdbee75f`，与 v0.5–v0.8 同一快照。
- 起点：v0.8 正式 run `b51e3635…` 的 PTR_seed42/43/44。冻结时核对：v0.8 manifest 的身份、所用题目注册、4B 快照与本轮一致；三个 adapter 的哈希与 v0.8 记录一致。（v0.8 adapter 自带的 efa-base.json 记的是 v0.8 那台机器的快照指纹，里面含下载标记文件的 inode 和 mtime，换机必然不同，所以改用 v0.8 manifest 证明基座。）每个 seed 的在线 run 从同 seed 的 PTR 出发。
- 条件（每个在线 run 占一整张卡）：
  - **RL**：RLOO，seed 42/43/44，lr 2e-5。
  - **RAFT**：只学做对的轨迹，seed 42/43/44，lr 2e-5，其余与 RL 完全相同。
  - **RLhi**（探索性）：RLOO，lr 5e-5，seed 42/43。用来看学习率敏感性，不参与任何判定。
  - B、PTR×3：本机重新评测，作参照。
- 采样：每步从该 seed 固定打乱的 pool 顺序取 16 题，每题 8 条对话（同一 seed 的 RL、RAFT、RLhi 看到同一串题，便于配对）。温度 1.0，不截断（top_p=1，不设 top_k），因为策略梯度要求行为分布就是训练时计算 log 概率的那个 softmax。vLLM 与训练进程在同一张卡上，每步更新后把新 LoRA 写盘，vLLM 用新的 id 重新读入。
- 奖励：最终提交的 SQL 重新执行，与 train 金标结果按项目判分一致记 1，否则 0（SQL 错误、超时、未提交、上下文拒绝、协议错误都算 0，留在分母里）。金标结果只在 oracle 里，不进入任何提示或工具返回。金标执行失败的题整组不训练（记数）。
- 目标（一次采样只做一步更新，纯 on-policy，不需要 PPO 的比率裁剪，也不复用旧轨迹）：
  - RL：优势 A_i = r_i − 同组其余 7 条奖励的均值（RLOO，组内全对或全错时为 0，不按标准差缩放）。
  - RAFT：A_i = r_i。
  - 损失 = −Σ_i A_i · Σ_t w_t · log π_θ(y_t) ÷（16 × 8 × 512）。t 取轨迹里每一轮实际采样的助手 token（含结束符）；工具结果、题目和历史只作条件。分母是常数，不按轨迹长度平均（Dr. GRPO 的做法），长短轨迹不因自身长度被重新加权。
  - w_t = min(π_θ(y_t) / π_vLLM(y_t), 2)，即截断重要性权重。同一份权重下，vLLM 与训练框架的 bf16 数值仍有差别，这一项修正训推不一致，并把差值作为诊断量记录。
  - 不加 KL、不加熵奖励。AdamW（无权重衰减），前 5 次更新线性预热，之后学习率不变；梯度范数裁剪 1.0；LoRA r16/α32 沿用 PTR 的那一套继续训练，训练时关闭 dropout（采样没有 dropout）。一步内没有任何非零优势时不做 optimizer step，题目照样消耗。
- token 进、token 出：生成器记录每轮的提示 token、采样 token 和 vLLM 给出的 log 概率。最后一轮的提示已经包含之前每一轮经对话模板重新渲染后的 token，所以整条对话按一条序列训练。如果某一轮文本重新分词后与采样 token 不同，这条轨迹不进梯度（仍算在组的基线里），并记数。本机用真实分词器和 v0.8 PTR 的 1501 条 test 对话核对过，按规范分词全部对齐。
- 训练步数与比较点：计划上限 200 步，每 10 步存一个里程碑 adapter。所有在线 run 都在 `until`（计算截止前 45 分钟）停止。**评测点 K = 六个主 run（RL、RAFT 各三个 seed）都到达的最大里程碑。** 某个主 run 的最后里程碑不到最好那个的一半时，记为“过短”，不拉低 K，只在它自己的最后里程碑上评测并单独标注。RLhi 在 min(K, 自身最后里程碑) 评测。不看任何验证分数挑步数。
- 学习曲线（描述用）：每个在线 run 在第 0、20、40… 步用当前 LoRA 在 dev 上贪心评一次，只作曲线，不参与任何选择。
- 评测：贪心，dev / validation / test，条件包括 B、PTR×3、RL×3、RAFT×3、RLhi×2（都在里程碑 K）。主指标为项目判分，官方 EX 并列；区间为数据库×seed bootstrap 95%。

## 预注册比较与判定

- **主比较 RL−PTR**（项目判分）：test 均值 > 0、95% 下界 > 0，且 validation 均值 > 0，判为成立。标准与 v0.7、v0.8 相同，按 seed 配对。
- **次比较 RL−RAFT**：同一标准。
- 探索性：RAFT−PTR，RLhi−PTR，RLhi−RL（RLhi 若在比 K 早的步数评测，报告时注明），各家族 −B，官方 EX，训练过程（奖励、有信号组占比、熵、轮数、生成长度、训推 log 概率差、TIS 截断比例），dev 学习曲线，错误类型与行为变化（`errors.py`）。
- 最终家族：PTR、RL、RAFT 中 dev 三 seed 均值最高、且三个 seed 在 dev 上都完整的那个；validation 与 test 不参与选择。

## 上机先排风险（本机已做与上机第一小时）

- 本机：CPU 测试覆盖 RLOO/RAFT 优势、轨迹对齐（重分词、截断、非常规结束符）、批量 log 概率、截断重要性权重、梯度检查点下每个 LoRA 权重都有梯度、LoRA 检查、断点恢复与重放、里程碑规则、评测与报告、调度器全流程、BIRD 并行下载与回退。用随机初始化的小 Qwen3 和脚本化引擎跑通完整在线 run（两步、断点、恢复）。这些都不是模型结果。
- 上机门禁：vLLM 用 PTR LoRA 实际采样，并返回采样 token 的 log 概率，失败即停。
- 冒烟 run（每个角色 16 题；RL、RAFT 各 2 步，每步 4 题 × 4 条）在前两张卡上跑完整路径，正式在线 run 等两个冒烟 run 都完成才开始。
- 每个 run 的第一步先做 **LoRA 检查**（取 32 条轨迹，几千个采样 token）：vLLM 给出的采样 log 概率，与训练端“基座 + 起点 LoRA”的平均绝对差必须小于与“光基座”的平均绝对差，而且小于 0.15 nat/token，否则立即停，说明 vLLM 没在用要训练的那个策略采样，或者 token 没对齐。两个框架之间的内核噪声大致对称，与 LoRA 改了什么无关。所以只要 vLLM 确实带着 LoRA 采样，前者平均下来一定更小，即使 LoRA 的作用很小。如果起点 LoRA 对这些 token 几乎没有影响（平均差 < 0.005），这个检查无从判断，记为 inconclusive，不停机。本机实测：在 PTR 自己的贪心输出上，PTR 相对基座的平均差是 0.03–0.15 nat/token，中位数为 0。所以不能用“差一半”这类阈值，否则会误停。
- 正式 run 开始后每 30 分钟导出一次结果包（奖励、指标、dev 曲线），本机可以边跑边看。

## 不声称的内容

- 不声称 RL 一定提升：一晚、LoRA、约 100–200 步、每步 128 条对话，规模远小于公开工作，结果好坏都如实报告。
- RL−RAFT 回答的是本设置下“负样本与基线”的作用，不推广到其他任务或规模。
- 执行结果一致只说明在固定数据库快照上结果相同，不等于语义等价；项目判分要求行数、列数、多重集都一致，比官方 EX 严格，奖励按项目判分给，官方 EX 并列报告，用来查看是否只是学会了迎合判分。
- 单晚、单一数据集（BIRD），结论只适用于本协议。
