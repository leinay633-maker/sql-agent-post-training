# v0.7 预注册：32B 老师蒸馏 vs 自我拒绝采样（4B），附 14B 自我训练

写于 2026-10-12（北京时间），在任何 v0.7 运行之前。协议 `efa-v7-teacher-distill-v1`。v0.6（Coder-7B 两轮迭代）没有正式运行，由本协议取代；v0.6 的 vLLM 生成、参考结果缓存和 ```json 解析沿用。

## 为什么有 v0.7

v0.5（Qwen3-4B，自己采样、执行验证后微调）在最终测试（BIRD dev 1501 题）上官方 EX：B 49.2%，R 52.2–53.1%，P 53.4–54.3%（3 seed）。同晚探索轮显示每题采样从 2 条加到 16 条没有额外收益（R16 与 R2sub 持平），说明在 4B 自己能做对的题里多采样不再带来新信息。v0.7 检验两件事：

1. **主问题**：用更强的模型（Qwen3-32B）生成、同样经执行验证筛选的轨迹，在同样的数据量下，是否比 4B 自己的轨迹训练得更好（T vs R）；把老师轨迹补到 4B 做不对的题上是否有额外收益（TR vs R）；执行验证这一步对老师数据值多少（T vs T_raw，探索性）。
2. **辅助问题**：同一套自我训练方法在 14B 上是否仍有提升（R14 vs B14，探索性）。

## 固定内容

- 题目：沿用 v0.5 注册（pool 6682 / dev 615 / validation 1612 / test 1501；test 为 BIRD 官方 dev 去掉参考 SQL 预检排除的 33 题），新机器上重新校验题目文件与数据库哈希。
- 模型（固定 revision，逐文件 SHA-256 校验；HuggingFace 与 ModelScope 文件字节相同，任一来源下载均按同一份哈希核对）：
  - 学生：`Qwen/Qwen3-4B-Instruct-2507` @ `cdbee75f17c01a7cc42f958dc650907174af0554`（与 v0.5 同一快照，快照指纹 `45ba5b8b…`）
  - 老师：`Qwen/Qwen3-32B` @ `9216db5781bf21249d130ec9da846c4624c16137`
  - 规模对照：`Qwen/Qwen3-14B` @ `40c069824f4251a91eefaf281ebe4c544efd3e18`
- 非思考模式：32B 和 14B 是混合思考模型，官方模板对历史轮次与当前轮次的渲染不一致，多轮按轮掩码无法做到前缀一致。两者统一用固定模板：每个助手轮次都写成空思考块 `<think>\n\n</think>\n\n` 加内容，生成提示同样以空思考块结尾；采样、评测和 14B 训练用同一模板。4B 用自带模板。
- Agent：v0.5 的无金标多轮状态机（最多 4 步，含一次结果复核），无列描述；上下文 8192，单步输出 512 token；动作解析接受裸 JSON 或“恰好一个 ```json 代码块包裹的对象且无其他文字”（所有条件相同）。生成停止符取模型 `generation_config` 的 eos（151645、151643）。
- SQL 限制：10 亿 VM 步为主约束，墙钟 30 秒只作兜底（v0.5 为 10 秒；v0.6 文档写的 60 秒作废），1 万行，8 MB。dev、validation、test 的参考 SQL 结果在冻结时执行并缓存（失败重试 3 次），评测按缓存判分。
- 采样：vLLM，T=1.0、top_p=1、top_k=0（与 v0.5 相同），老师和 14B 对 pool 每题各采 **K=2** 条（与 v0.5 4B 自采每题约 2.04 条对齐）；同一题的 K 条连续调度；按 64 片认领；老师每轮墙钟上限 90 分钟，14B 45 分钟，未采满按实际覆盖报告。判分只在 train 题上用 gold，gold 不进入任何模型可见内容。
- 训练：与 v0.5 R 完全相同的训练器和超参（LoRA r16/α32/dropout 0.05/all-linear，lr 2e-4，warmup 3%，线性衰减，每步 16 例，1 epoch，最长 8192 token，超长整题跳过，seed 42/43/44 只改初始化与顺序）；4B 微批 4×累积 4，14B 微批 2×累积 8（损失按每步总监督 token 归一，梯度等价）。训练后重载 logits 校验。

## 比较（全部报项目判分与官方 EX）

- **主比较**：`T − R`（seed 配对，数据库×seed bootstrap 95%），test（BIRD dev 1501 题）为主，validation 作复现。
- 次要：`TR − R`、`TR − T`、`T − B`、`R − B`、`TR − B`；`P_X − X`；`T − T_raw`（seed42，探索性）；`R14 − B14`（探索性）；B32 与 4B 各条件的绝对水平对照（差距收窄比例 `(T−B)/(B32−B)` 只作描述）。
- 成功标准（主问题）：test 上 `T − R` 均值 > 0 且 95% 区间下界 > 0，并且 validation 上均值 > 0，才写“老师蒸馏优于自我训练”；否则如实写不支持。`TR − R` 用同一标准。

## 选择（只看 dev）

- 最终系统：在 {R, P, T, TR, P_X} 中按 dev 上 3 seed 平均（项目判分）最高的家族（3 个 seed 都评完才参选）；`P_X` 的 X 也只按 dev 选。test 不参与任何选择。
- 投票推理 `+vote`（8 条采样 T=0.8/top_p 0.95，按执行结果取最大组，不用金标）：只对最终家族的 seed42 跑，validation 上高于 greedy 才作为最终推理方式；时间不够就不跑。

## 时间安排（8×H20，约 8 小时；全部由调度器按依赖执行）

开机即并行：环境、BIRD、三个模型下载（4B、14B 优先，32B 后台继续）→ 冻结 → **全流程冒烟**（极小子集，覆盖每种作业，数字永不作结果）→ 14B 采样（8 卡）→ 老师采样（8 卡）→ 选样 → 4B 训练（T×3、TR×3、T_raw）与 R14 seed42 → 各条件评测（dev/validation/test）→ 按 dev 选 X → P_X ×3 → 最终家族 `+vote` → 报告。每阶段自动追加进度并打包结果。

## 不做

不在看过 validation/test 分数后改设置；不挑 seed；冒烟子集的数字永不当结果；OOM、吞吐不足、下载慢只写进报告，不中途换配置续算；不使用列描述（v0.6 的列描述证据只在 test 上较明显，不能据 test 做设计决定）。

## 已知风险

32B 单卡 vLLM 的吞吐未实测（按 4B 实测每卡每分钟 360 条外推约 45 条，K=2 全 pool 约 40 分钟）；32B 下载 65.5 GB 的耗时取决于机房带宽；14B 训练按 4B 实测（46 分钟/3435 例）外推约 2.7 小时；4B 的 R/P 是在上一台机器上训练的（同一训练代码与依赖版本），T/TR/T_raw 在本机训练。
