# v0.10 预注册：分布式全参数在线 RL（4 卡 vLLM 采样 + 4 卡 FSDP2 训练，每步同步权重），对照 v0.9 的 LoRA RL

写于 2026-10-19（北京时间），在任何 v0.10 运行之前。协议 `efa-v10-dist-full-rl-v1`。

## 为什么有 v0.10

v0.9 是单卡 LoRA 在线 RL：vLLM 和训练进程在同一张卡上，每步更新后把新 LoRA 写盘重载。上机实测（10-19 正在跑的 v0.9 正式 run）每步 37–44 秒，其中 128 条对话采样 18–20 秒、LoRA 训练 15–20 秒，训推 log 概率差 0.002–0.005 nat/token，峰值显存 18–21 GB。一张卡就装得下，八张卡只是八个互不相干的 run。

v0.10 把同一个训练问题改成一个必须多卡才成立的系统：四张卡各跑一个 vLLM 采样 worker，四张卡用 FSDP2 训练全部 40 亿参数，每一步把新权重同步给所有 worker。问题：

1. **主问题**：起点、题目、采样、奖励、目标和步数都与 v0.9 相同，只把 LoRA 换成全参数更新，结果是否比 v0.9 的 LoRA RL 更好（RLF − RL）。
2. **次问题**：全参数 RL 相对起点 PTR 是否提升（RLF − PTR）。
3. **探索**：一步异步（RLFa）比同步快多少、效果差多少；每一步的时间花在哪里；训练端两种分片方式的代价。

## 固定内容

- 题目、Agent 协议、判分、奖励、采样与目标：与 v0.9 完全相同。冻结时逐项核对 v0.9 manifest：采样盐、每步 16 题 × 8 条、温度 1.0、最多 4 步（含一次结果复核）、单步 512 token、上下文 8192、SQL 执行限制、损失分母 16 × 8 × 512、截断重要性权重上限 2、预热 5 次更新、梯度范数裁剪 1.0，任一项不同即拒绝冻结。同一 seed 与 v0.9 看到同一串题。
- 学生：`Qwen/Qwen3-4B-Instruct-2507` @ `cdbee75f`，与 v0.5–v0.9 同一快照。
- 起点：v0.8 正式 run `b51e3635…` 的 PTR_seed42/43/44（v0.9 的起点），在机器上以 fp32 合并进全参权重，再取整到 bf16。合并前后用 128 个固定 token 比较 logits，fp32 下最大差必须 ≤ 1e-3；合并记录写明输入哈希、peft 版本和权重校验和。
- LoRA 臂：v0.9 正式 run `a21767fe…` 的 RL_seed42/43/44，取 v0.9 登记的共同里程碑 K（`steps.json`），同样合并成全参后评测。冻结时核对 v0.9 manifest 的身份、所用 v0.8 run、题目注册和 4B 快照，以及三个 adapter 的哈希与 v0.9 里程碑记录一致。
- **所有条件都按全参权重、走同一条 vLLM 推理路径评测**（B 是原始 4B，其余是合并或训练出的全参权重），RLF − RL 不混入“LoRA 在线挂载”与“全参”两种推理路径的差别。
- 条件：
  - **RLF**（同步）：全参 RLOO。第 s 步的轨迹用第 s 版权重（第 s−1 步更新后的权重）采样，训练完再发下一步的采样。seed 42/43/44。
  - **RLFa**（一步异步）：训练第 s 步时，第 s+1 步的采样已经用第 s 版权重开始，训练用的轨迹落后一版。截断重要性权重以 vLLM 采样时记录的 log 概率作行为分布，同时修正这一版之差和训推数值差。其余与 RLF 相同。
  - B、PTR×3、RL×3：本机重新评测，作参照。
- 优化：学习率 2e-6（v0.9 LoRA 的 2e-5 的十分之一，全参更新作用在全部参数上），AdamW 不加权重衰减，前 5 次更新线性预热，之后不变；梯度范数裁剪 1.0（全局范数跨所有分片计算）；训练时关闭 dropout（采样没有 dropout）。一步内没有任何非零优势时不做 optimizer step。不加 KL、不加熵奖励。
- 步数：K = v0.9 的共同里程碑（v0.9 跑完后由 `steps.json` 定，计划 200）。`configs/h20-v10.json` 的 `planned_steps` 必须等于 K，打包脚本和冻结都会核对。每 20 步存一份全参里程碑（每份约 8 GB）和一个 dev 曲线点，第 K 步必存。
- 只有跑满 K 步的 run 参与评测：每次预约是一台新机器，停在截止时间的 run 无法换机续跑，记为未完成。调度器只在估计能在截止前 40 分钟跑完时才启动一个在线 run。

## 系统

- 8 张 H20（NV18 全互联）：
  - 4 张各跑一个 vLLM 0.11.2 采样 worker（显存占比 0.85，128 条并发）。每步 16 题按整组连续分给 4 个 worker，每个 4 题 × 8 条。
  - 4 张跑训练（torch 2.10，一卡一进程，torchrun）：FSDP2 把 fp32 参数、梯度和 AdamW 状态全部分片，前向和反向用 bf16，每个解码层做激活检查点，`reshard_after_forward=True`（类 ZeRO-3）。
- 每一步：
  - 训练端 rank 0 发采样请求、合并各 worker 返回的组，算 RLOO 优势。
  - 有信号的轨迹按 token 量分给 4 个 rank（最长优先）。每个 rank 跑相同数量的 micro-batch，不足的用零权重填充，否则 FSDP 的集合通信会挂起。
  - 损失乘以 world size：FSDP 对梯度求平均，而 v0.9 的分母是每步常数。本机用单 rank FSDP2（bf16 计算）对照 v0.9 在 bf16 副本上的反向：loss 相差不到 5%，每个参数的梯度余弦相似度都大于 0.98。
- 权重同步：
  - 每次更新后逐参数 all-gather 成 bf16。rank 0 写到 `/dev/shm` 的 safetensors，最后写 ready 文件。
  - 各 worker 原地加载（`collective_rpc` 调 `load_weights`），然后清空前缀缓存。
  - 加载前后用 float64 的（和、平方和）校验。这个校验与 vLLM 是否把 qkv、gate/up 拼接无关，tied embedding 只计一次，单个 bf16 的一位变化也能看出来。不一致即停。
- 权重检查：每个 run 的第一步取 32 条轨迹，vLLM 采样 log 概率与训练端起点权重的平均绝对差必须小于 0.15 nat/token，否则停。v0.9 实测这个差是 0.002–0.005。
- 检查点：每 20 步用 torch.distributed.checkpoint 存分片的 fp32 参数和 AdamW 状态。中断后从最近检查点继续，被中断的那一步重新采样，旧记录另存为 `*.rolled-back-*`。调度器按剩余步数估时，决定还来不来得及重试。跑完的 run 删掉检查点，只留里程碑。
- 评测：贪心，dev / validation / test；条件为 B、PTR×3、RL×3、RLF×3、RLFa×3（后两者在第 K 步）。主指标为项目判分，官方 EX 并列；区间为数据库×seed bootstrap 95%。

## 预注册比较与判定

- **主比较 RLF − RL**（项目判分），按 seed 配对：
  - 成立：test 均值 > 0、95% 下界 > 0，且 validation 均值 > 0。
  - 反向成立：test 均值 < 0、95% 上界 < 0，且 validation 均值 < 0。
  - 可称无差别：test 的 95% 区间整体落在 ±2 个百分点内。
  - 其余：不成立（这个规模下分不出来）。
- **次比较 RLF − PTR**：同一标准。
- 探索性（不做判定）：
  - RLFa − RLF 的效果差，以及速度比（RLF 每步时间中位数 ÷ RLFa 的）。
  - RL − PTR：v0.9 的主比较，在全参推理路径上重测。
  - RLFa − PTR、PTR − B、RLF − B，以及官方 EX。
  - 训练过程：奖励、有信号组占比、熵、轮数、生成长度、训推 log 概率差、截断比例、梯度范数。
  - dev 学习曲线、错误类型与行为变化。
- 判定在三个 seed 都跑完后做：一次预约训完三个 seed，就用这次的报告；有 seed 没跑完、另约补跑时，用合并报告。少于三个 seed 的报告按同一标准计算、注明 seed 数，只作初步结果。

## 系统测量（描述，不做判定）

- 每一步的时间分解：等待采样、训练、优化器、权重 gather、写盘、存里程碑；每个 worker 的采样时间和加载时间；token/s；MFU（按 H20 稠密 BF16 148 TFLOPS 计）；峰值显存。
- 训练端版式基准：用正式 run 前 3 步保存的训练轨迹，只跑训练，比较类 ZeRO-3 与类 ZeRO-2（`reshard_after_forward` 为 True / False），各在 4 卡和 8 卡上测。每种版式重放两遍，第一遍是预热，单独列出，不计入中位数。
  - 排在收尾评测之后，约 25 分钟。基准和随后约 10 分钟的报告能在计算截止前 15 分钟一起跑完，基准才启动；排不上，这次预约就不测，由后面的预约补。合并报告取第一份各版式都测完的。
- 权重加载门禁（冒烟前）：
  - 加载一份只把最终 norm 乘 1.5 的权重，输出必须变化（平均 log 概率差 > 0.01，或贪心 token 变了）。
  - 再依次把每层的 v_proj、gate_proj 乘 2。在 vLLM 里它们是拼接张量 qkv_proj、gate_up_proj 的一段，走另一条加载路径。每次输出都必须相对上一次变化，校验和必须正好变化这几个张量的差。不用 q_proj、k_proj：Qwen3 对 q、k 逐头归一化，整体放缩不改变输出。
  - 加载完整起点权重恢复后，输出必须复原（最大差 ≤ 1e-3），校验和与记录一致。
  - 记录完整加载耗时。
  - 校验和的灵敏度（本机模拟，2^24 个元素按 40 亿换算）：lr 2e-6 的一步更新让约 7% 的 bf16 值翻动一个最小单位，“和”的变化是容差的 54–181 倍（预热第一步也有 2% 翻动）。所以“权重没换进去”会被逐步的校验和比对发现。

## 预约与每次的范围

- 一次 8 卡 13 小时的预约训三个 seed。
  - 冒烟先行。三个 seed 的 RLF 依次跑完，再按剩余时间依次跑 RLFa；排不进的不启动，报告注明。
  - 计算截止为回收前 25 分钟。
- 在线截止线：在线 run 必须在计算截止前 40 分钟跑完，每多训一个 seed 再提前 15 分钟，三个 seed 是 70 分钟。
  - 这段时间留给第 K 步的评测、报告和导出。每多一个 seed，收尾就多评测 4 个条件 × 3 个角色。
- 估时（v0.9 实测换算）：同步约 30 秒一步，一步异步约 18 秒。
  - 本机测到之前，调度器按 45 / 35 秒保守估计。
  - 测到之后，用该家族实测平均步长的 1.1 倍。用平均数不用中位数，是因为 v0.9 的采样有长尾（RL_seed42 每步中位数 36 秒、平均 45 秒），而一个 run 的时长是各步之和。
  - RLFa 跑之前，按 RLF 实测的每步“等采样”和“其余部分”两者中较长的那段估计，因为异步时两者重叠。
  - K = 200 时，RLF 约 1.7–2.5 小时（采样长尾重时接近 3 小时），RLFa 约 1.0–2.0 小时。
- 某个 seed 的 RLF 这次没跑完时，另约一次补跑，各次的正式 run 用合并报告汇总。
- 机器到点回收：每个正式 run 跑完后，调度器立即把它第 K 步的全参模型（约 8 GB）切成 1 GiB 分片、附清单导出，本机在回收前拉回，以便日后补评测或复查。
- 修订记录：原计划每次预约 7 小时、只训一个 seed（10-23 跑 seed 42，下周跑 seed 43、44）。2026-10-19 在任何 v0.10 运行之前改成上面的一次 13 小时。
  - 原因：这次能约到一整段 8 卡 13 小时；装一次环境代替三次；三个 seed 在同一台机器上。
  - 同时把在线截止线改为随 seed 数增加，估时从中位数改为平均数。
  - 收尾不再等这次没训成的 run 的评测；基准连同其后的报告一起估时；万一报告要靠兜底，兜底按剩余时间跑，超时也不把整次预约记成停止。
  - 判定标准、条件和训练设置都没变。

## 上机先排风险

- 本机 CPU 测试（随机初始化的小 Qwen3，tied embedding 同 4B，都不是模型结果）：
  - 配置与条件名；校验和对拼接、顺序不敏感，单个 bf16 变化可见；权重导出与写入往返。
  - token 量分片与零权重填充；请求分配保持整组和题目顺序；通道的请求、结果、权重与心跳。
  - 冻结核对两份导入；真实 LoRA 合并复现 LoRA 模型。
  - 单 rank FSDP2 梯度对照 v0.9 的目标。
  - 两个线程 worker + FSDP2 训练端的完整同步 run：中途崩溃、从检查点恢复，每个 worker 按顺序加载每一版权重。
  - 一步异步 run：第 1 步的轨迹用第 0 版权重采样（落后一版）；从检查点恢复后的第一步重新用最新权重。
  - 权重加载门禁能识别“加载没生效”的引擎；评测与报告；模型分片打包与本机重建（损坏的分片会被识别）。
  - 调度器全流程。
- 上机门禁：
  - 主环境四卡 NCCL all-reduce；vLLM 用 4B 实际采样并返回 log 概率。
  - 权重加载门禁。
  - 冒烟 run：每个角色 16 题；RLF、RLFa 各 3 步，每步 4 题 × 4 条，训练 2 卡 + 采样 2 卡，两组并排。每个冒烟 run 中途停一次再从检查点恢复，在 GPU 上走一遍恢复路径。
  - 正式 run 等两个冒烟 run 都完成才开始。冒烟的评测与报告排在最后，只用剩下的卡，不推迟正式 run。
  - 门禁不通过或冒烟 run 放弃时，正式 run 不启动，B、PTR、RL 的评测随即开始。
- 正式 run 开始后每 30 分钟导出一次结果包（奖励、指标、dev 曲线、系统计时），本机可以边跑边看。

## 不声称的内容

- 不声称全参一定好于 LoRA。规模是 K 步、每步 128 条对话、一个数据集（BIRD）。
- RLF − RL 同时改了两件事：可训练参数（全部参数对 LoRA r16）和学习率（2e-6 对 2e-5）。学习率只设了一个值，没有扫，差别不能全归因于“全参”。
- 一步异步的速度比取决于采样时间与训练时间之比，只在本负载下成立。
- 系统数字只适用于本机型（8×H20、NV18）、本模型（4B）、本负载。
- 执行结果一致只说明在固定数据库快照上结果相同，不等于语义等价；奖励按项目判分给，官方 EX 并列报告。
