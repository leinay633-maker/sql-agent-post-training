# v0.6 预注册：7B 代码模型上的迭代执行验证 RFT

写于 2026-10-11 23:20（北京时间），在任何 v0.6 运行之前。协议 `efa-v6-iterative-rft-v1`。

## 为什么有 v0.6

v0.5（Qwen3-4B，HF 生成）在预注册口径下 R−B 为正，官方 EX 口径 BIRD dev 上 B 49.2% → R 52.2–53.1%，但绝对水平低于同规模公开系统（约 59%–64% 的 7B 系统）。同晚的探索性证据（非预注册）：①vLLM 采样约 9.5 倍于 HF，评测约 8.5 倍，greedy 判对一致 1469/1501；②每题 16 条采样把边界题从 458 提到 1562（同一批题前 2 条对照）；③BIRD 列描述在 4B 上 validation +0.7 个百分点（R seed42：923 → 934）。v0.6 一次性改：基座、生成引擎、采样数、列描述、第二轮迭代。各项单独贡献不在本轮拆分，结论只针对整体配方相对同一基座 B 的提升，以及第二轮相对第一轮。

**23:55 补充（探索轮评测结束后、任何 v0.6 运行之前）**：边界题变多并没有变成模型提升。test（BIRD dev，各条件最终 SQL 超时 0–5 题，未受污染）上，vLLM greedy：B 669/1501（44.6%），R16（每题 16 条）三 seed 平均 47.5%，R2sub（同一批题只用前 2 条）47.6%，v0.5 R（HF 采样）seed43/44 平均 47.5%。也就是说，在 4B、单轮、每题最多选 1 条的规则下，采样数从 2 加到 16 没有额外收益。validation 上 R16、R2sub 和两个 vote 条件作废：16 个评测并发时 donor 库的 SQL 被 10 秒墙钟截断，每个条件有 48–105 道最终 SQL 超时（B、R_r1 为 0–3）。因此 v0.6 仍用每题 16 条，理由只是第二轮需要足够的边界题覆盖，而 vLLM 下这只多花约 80 分钟；不再把“16 条优于 2 条”当作已知收益。v0.6 的提升预期来自 7B 代码基座和第二轮迭代，这正是要检验的。列描述：R seed42 在 validation +0.7（923 → 934），B 在 validation −0.4（881 → 874），证据很弱，作为固定配方的一部分保留，不单独宣称作用。

## 固定内容

- 题目：沿用 v0.5 注册（pool 6682 / dev 615 / validation 1612 / test 1501，BIRD dev 去掉参考 SQL 预检排除的 33 题），文件哈希与数据库哈希在新机器上重新校验。
- 基座：`Qwen/Qwen2.5-Coder-7B-Instruct` @ `c03e6d358207e414f1eca0bb1891e29f1db0e242`，BF16。不做基座筛选。
- Agent：与 v0.5 相同的无金标多轮状态机（最多 4 步，含一次结果复核），用户 JSON 额外给出 BIRD `database_description` 列描述（公开元数据，非金标），按 token 预算（首轮提示 ≤ 10000）选最大档，冻结在 `column_notes.json`；上下文 16384，单步输出 768 token。
- 动作解析：除裸 JSON 外，也接受“恰好一个 ```json 代码块包裹的 JSON 对象且无其他文字”。依据：今晚 24 题冒烟中 Coder-7B 采样的协议错误 179 次里 135 次正是这种格式（其余为前后夹带说明文字、未知动作 answer 等，仍记协议错误）。这是协议定义的一部分，所有条件相同。
- SQL 预算：指令上限 10 亿 VM 步（单线程约 6 秒）为主约束，墙钟 60 秒（`Limits` 允许的上限）只作兜底（v0.5 为 10 秒墙钟），避免机器负载把同一条 SQL 从通过变成超时；今晚的探索评测中，高并发让 donor 库上每个条件 48–105 道题的最终 SQL 因 10 秒墙钟超时而判错。报告逐条件列出最终 SQL 超时数和对话内查询超时题数；某条件超时数明显高于 B 时，该条件的比较标为受污染，不进结论。
- 采样：vLLM，T=1.0、top_p=1、top_k=0，第一轮基座每题 16 条，第二轮用 `R_r1_seed42` 每题 16 条；按条数分 64 片认领，墙钟上限每轮 80 分钟（未采满按实际覆盖如实报告）。
- 选样与训练：v0.5 的选样规则（边界题优先、每题 1 条、报错动作与被改掉的错误提交不计损失）与 LoRA 训练器原样复用（r16/α32，lr 2e-4，每步 16 例 = 微批 2 × 累积 8，1 epoch），上限 8192 例、长度 12288；第一轮 R×3 seed（42/43/44）+ R_clean seed42；第二轮 R×3，从基座重新训练（ReST-EM 式），数据只来自第二轮采样。
- 第二轮是否运行：第一轮训练结束时，剩余时间 ≥ 第一轮实测采样时长 + 训练时长 + 40 分钟评测预留 + 10 分钟，才运行；否则跳过并如实写明。
- 评测：vLLM greedy；参考 SQL 结果在冻结时执行一次并缓存（修 v0.5 dev 并发超时）；每个条件不同题目顺序、SQL 并发 ≤ 16。投票 `+vote`：8 条采样（T=0.8、top_p=0.95），按执行结果（列数 + 行多重集合）取最大组，平票取最早一条；不使用金标。
- 指标：主指标为项目执行匹配（多重集合、行列数一致）；同时报官方 BIRD EX（只重跑记录的最终 SQL，集合相等，30 秒超时）及全部 1534 题的下界。差值为按 seed 配对、数据库×seed bootstrap 95% 区间。

## 比较与选择（只看 validation）

- 主比较：`R_r1 − B`、`R_r2 − B`、`R_r2 − R_r1`（3 seed 配对），validation 与 test 都报。
- 最终系统：在 validation 上 3 seed 平均更高的家族（R_r2 需 3 个 seed 都完成），其 seed42；若该模型 `+vote` 在 validation 上高于 greedy，则用 `+vote`。test 上报所有条件，test 不参与任何选择。
- 消融（探索性）：`R_r1 − R_clean_r1`（修复轨迹的作用）、`B+vote − B`。

## 不做

不在看过 validation / test 分数后改设置；不挑 seed；冒烟子集（manifest 中 `smoke_limit > 0`）的数字永不当作结果；OOM 或吞吐不足只能写进报告，不能中途换配置续算。
