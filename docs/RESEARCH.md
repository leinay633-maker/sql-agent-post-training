# 研究协议 v0.3

## 主问题

固定 Qwen 基座、数据库隔离、相同生成预算下，修复上下文 SFT 是否优于普通成功答案 SFT？主比较为 D−C，B−C/D 辅助判断训练价值；A 与 B 的差异包含额外计算和执行反馈，不能归因于训练。

C/D 使用同一组训练任务 ID、同一个最终 SQL、相同 seed/优化步数/LoRA 配置；C 是干净问题/Schema→最终答案，D 增加错误与实际执行反馈→相同最终答案。所有历史 assistant 动作也 mask；两组输入 token 不同，必须同时报告输入、受监督 token 和实测训练成本。不是“更大训练集”对比，也不是强化学习。

## 数据与反馈

官方 train 按数据库分训练/验证，来源、原始文件、数据库与代码均保留版本/哈希。本轮 H20 配置使用 512 个训练候选、256 个数据库/难度均衡验证题，训练 seeds 42/43/44。三个 seed 共享一份语料、数据划分及256题验证集，A/B各只运行一次；它们不是三份独立数据集。选题只依赖固定 seed 和元数据，不看模型分数。测试集、Mini-Dev、官方 dev 不进入采样、prompt 调优或轨迹筛选；后续独立最终测试另行登记，不篡改本轮历史。

natural 只保留真实模型中出现执行失败或错误提交答案、随后真正修好的轨迹。正常探索查询不自动算语义错误。mixed 在自然修复不可用时用 rule_perturbation 补足，记录筛选前后总量、来源比例、错误类型和所有拒绝原因。规则增强中“能执行”的 SQL 必须实际得到与训练 gold 不同的结果，不能只凭 SQL 文本不同认定错误。

每条 repair 轨迹在实际 SQLite 环境重放，核验消息和反馈，再独立执行最后 SQL；不能信任输入文件中 `correct=true`。错误示例只在训练构造时比较 gold，评测端看不到 gold、正确性分数或按 gold 触发的重试。

v0.3 的 B/C/D 统一启用实际结果复核：未得到过查询反馈就提交的答案，可看到一次真实结果预览并决定修正；查询已有反馈则不额外重复目标答案。最多仍为 4 次生成。A 一次直接提交。协议和 batch size 写入运行身份，不与旧 v0.2 混算。

## 首轮统计与可信度

保留所有题目为分母，单列 SQL 错误、协议错误、资源限制、无效 gold、未完成、模型异常；v0.3.1在选题之前统一执行参考SQL筛选并冻结排除名单，抽不满登记分母就停止；选题后的gold仍是硬门禁，失败先停机修复，不静默删评测题。结果判分保留重复、NULL、列数、显式排序及浮点规则，截断不判对；这不是 BIRD 官方打分实现。

批量模式只聚合生成，不共享题目之间的消息或 gold。greedy、相同输出预算、固定 batch size；pilot 记录 scalar/batch 的差异，不把浮点实现差异伪装成严格数值等价。OOM 停止，不在正式实验内自动换 batch/精度。

256 题并不自动保证功效：数据库相关性、配对不一致率和效应大小都重要。报告每个训练seed的数据库聚类配对bootstrap区间，三份D−C全部保留，并可列描述性均值/标准差；不把256题重复三次当768独立题，不按最好seed下结论。小卡单seed配置只作探索，不代表对训练随机性稳定。均衡抽样的聚合值不代表完整数据分布；主比较预先确定，不能多次比较挑最好的一组。

报告必须同时包含原始逐题结果、来源/成本、自然与规则样本比例、提升及退化案例。方法失败或无显著改善也保留，不预设目标收益；pilot 的 8 题训练集指标不能写成泛化成绩。

## 实验门禁与回收

本次13小时窗口的多卡/单卡配置、固定30B缓存、绝对截止、本机拉取和v0.4接续见 H20_8GPU_RUNBOOK.md（未公开）；历史基础安装见 H20_RUNBOOK.md（未公开）。GPU 不存 GitHub 凭据。数据哈希不能证明许可，执行正确也不能证明超出该数据库的 SQL 语义等价。LLM 预训练污染无法靠本项目的拆分审计消除，必须作为限制保留。

本轮不引入DDP、vLLM、按效果选seed或前端扩建。额外30B A/B只作为同注册题目的容量对照，保持输出/交互预算，单列batch与成本差异，不与4B的训练归因报告混算。v0.4使用独立两轮执行奖励协议，必须等整个v0.3.1完成并回收到本机后，再做train-only pilot与预算判断，不挤占主研究。只有代码、测试、训练、独立验证和本机证据都存在，才可以报告实际成果。
